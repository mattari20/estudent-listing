## Purpose
Maintain the authoritative entry point for project decisions, requirements, architecture, data lifecycle, implementation status and delivery roadmap. Do not treat a feature as complete solely because code exists; completion requires tests and the appropriate live verification.

## Product direction
Build a modular, long-lived directory for Pakistani education institutions across education levels, from lower-level schools and colleges through universities and other eligible institutions. Help students discover, compare and understand institutions, campuses, programs and admissions using reliable, current, source-backed information.

## Status vocabulary
- **Implemented in code:** relevant implementation is present.
- **Automated-test verified:** relevant automated tests pass on the reviewed commit.
- **Live verified:** current deployed behaviour was observed and recorded.
- **Planned:** approved future requirement, not represented as delivered.
- **Blocked / needs investigation:** evidence is missing or a known defect remains.

## Operating rule
Every change must reference a requirement, include appropriate tests, preserve data-safety controls, and update the implementation register. Keep a dated report of deployment and database diagnostics; never present historical counts as current.
