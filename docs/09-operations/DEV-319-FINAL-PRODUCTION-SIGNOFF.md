# DEV-319 — Final Production Release Sign-off

## Purpose

DEV-319 provides a single read-only application-level sign-off report for the Institutes & Education Directory.

It does not promote imports, mutate canonical records, change source evidence, or publish data.

## Sign-off checks

The report verifies:

- application debug is disabled by default
- session cookies are HTTP-only
- SameSite is lax
- production session cookies default to secure
- institute operations routes are protected by authentication and the operator middleware
- required public institute routes exist
- required v1 institution API routes exist
- application validation workflow is present
- production validation runbook is present
- production security hardening documentation is present
- composer.lock exists for dependency reproducibility

The report returns the exact failed checks as blocking_findings.

## Endpoint

The report is available to authenticated institute operators at:

GET /institutes/operations/production-signoff

The endpoint is read-only.

## Release interpretation

production_signoff_ready=true means all application-level checks passed.

production_signoff_ready=false means at least one blocking prerequisite remains.

The sign-off report does not claim that GitHub Actions, the live hosting environment, the production database, DNS, HTTPS certificate, backups, or external source websites were successfully validated. Those require execution in their respective environments.

## Dependency reproducibility

A committed composer.lock remains a release prerequisite. The project must not use a fabricated lock file. It should be generated by Composer against the declared dependency constraints in an environment with package repository access, then committed and validated by CI.

## Final release principle

No production data promotion should be treated as complete solely because this report exists. The report is one final application contract within the broader production validation runbook.
